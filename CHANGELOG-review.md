## Блокеры

### 1. ПДн в DeepSeek/Gemini — выключено по умолчанию
- `engine/intlServer.js`: AI-варианты ответа теперь за флагом `INTL_AI_OPTIONS` (по умолчанию `false`).
  Ключи читаются из конфига (`DEEPSEEK_API_KEY`, `GEMINI_API_KEY`), а не из `process.env` напрямую.
  Гейт: флаг + ключ + (для `CHANNEL_MODE=live` обязателен `REAL_DATA_ALLOWED=true`).
- Кэш вариантов ограничен: `AI_OPTIONS_TTL_S` (900 с) и `AI_OPTIONS_MAX` (200 записей), плюс дедупликация
  одновременных запросов (раньше `Map` рос без предела и отдавал устаревшие слоты/цены).
- `POST /v1/intl/leads/:id/ai-drafts` при выключенном флаге не ходит в сеть: `{ai_enabled:false, engine:'fallback'}`.
- `core/intl/voice.js`: ключ Gemini больше не передаётся в query string (заголовок `x-goog-api-key`);
  в шапке отмечено, что модуль не подключён к движку, а при подключении должен идти через тот же флаг.
- Старт процесса пишет `ai_options_enabled` / `ai_options_disabled` — состояние видно в логах.

### 2. Атомарная бронь просмотров — `core/intl/booking.js`, `core/intl/store.js`, `db/migrations/005_*`
- Слот резервируется условным `UPDATE ... WHERE status='free'` (проверка числа изменённых строк), поэтому два
  одновременных бронирования на один слот дают одну бронь и `409 slot_unavailable`.
- Повторная бронь той же пары `(lead_id, slot_id)` идемпотентна; добавлен `UNIQUE(lead_id, slot_id)`.
- Проверка принадлежности: лид может бронировать только слот своего объекта.
- `setViewing('confirmed')` — условный переход только из `unconfirmed`; `cancelled` освобождает слот.
- Миграция `005_intl_viewing_unique.sql` применяется автоматически для Postgres; SQLite-схема обновлена,
  существующая база не ломается.

### 3. Retention — `core/intl/service.js`
- `sweepRetention` обнуляет `dedup_key` и `channel_msg_id` вместе с текстом/именем: Telegram chat id больше
  не остаётся в базе после обезличивания.
- `retention_until` продлевается при новых входящих: активный диалог не стирается внезапно на 30-й день.

## Архитектура: реактивный стейт, ошибки, валидация, retry

- Настройки заканчиваются на пункте 6 (ручное подтверждение, автоответ HOT, стиль диалога,
  утренний дайджест, пометка ИИ, строка STOP). Блоки «Быстрый старт», инструменты и CSV убраны.
- `ui-intl/store.js`: минимальное реактивное хранилище (get/select/set/update/subscribe, батчинг
  микротаском). В приложении через него живут глобальная ошибка и online-статус: обновляется только
  баннер, экран не перерисовывается. Рендеры экранов склеиваются через requestRender().
- `core/intl/retry.js`: экспоненциальный backoff с джиттером, учёт Retry-After, `withRetry` и
  `fetchWithRetry`; повторы только для идемпотентных вызовов (Green API state/settings/QR, polling).
  Отправки сообщений не ретраятся — от дублей защищают idempotency keys.
- `core/intl/validation.js`: строгие проверки Telegram token, Green/Cloud кредов и gateway payload;
  ошибки возвращают машинный код и поле. Подключение WhatsApp валидируется и на клиенте, и на сервере.
- Boot-guard: live-режим отклоняет битые TELEGRAM_BOT_TOKEN / WHATSAPP_* с кодами
  telegram_token_invalid / whatsapp_credentials_invalid.
- Глобальный перехват ошибок: window error/unhandledrejection → баннер с «Повторить» и POST

  GET/PUT/DELETE и запросов с Idempotency-Key, учёт Retry-After.
- Строгая типизация: `tsconfig.strict.json` (allowJs + checkJs + strict) для retry/validation/store;

## WhatsApp Cloud API (официальный канал Meta)

- Новый канал `whatsapp`: входящие текстовые сообщения через вебхук Meta (`GET/POST /v1/intl/whatsapp`),
  проверка verify-token и подписи `X-Hub-Signature-256` (HMAC-SHA256 от сырого тела), дедупликация по
  `message.id`, кнопки/интерактивные ответы приводятся к тексту.
- Исходящие: `POST https://graph.facebook.com/{api}/{phone_number_id}/messages`; токен, phone number ID,
  verify token, app secret, версия API — через `.env`; в Setup появляется строка проверки WhatsApp.
- Честные ограничения: только текст и ссылки (медиа/голос — нет), вне 24-часового окна Meta требует
  шаблон — отправка вернёт `template_required`/`window_closed`, а не поддельный успех; без
  `WHATSAPP_APP_SECRET` вебхук в live не принимается (503).
- `WHATSAPP.md`: пошаговая настройка Meta (app, номер, permanent token, webhook, подписка на messages),
  требования к live-режиму и чек-лист проверки. `.env.example` дополнен.
- UI: каналы Telegram / WhatsApp / Симулятор, Setup «Подключите Telegram Business или WhatsApp Cloud API»,
